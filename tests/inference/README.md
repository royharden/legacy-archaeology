# Candidate and filler regression source

Authored under Dirty Mode; **not collected, imported, or executed**. AST parsing
only establishes syntax. No candidate recall, conversion parity, benchmark,
runtime security, or product acceptance was measured.

Hand-written cases check bounded span/name/policy units; exact authorized
evidence; stable generation identities and stale source/brief/authorization
changes; explicit sign/scale/padding/century/sentinel policies; zero-date refusal
to become a null shortcut; unknown for omitted combinations; missing vocabulary
diagnostics; and explicit filler declarations that create no approval or journal.

All layout bytes and expected policy identities are public local test data. No
evaluator/scorer/converter algorithm or hidden asset is used to derive expected
values. Field spans are not a quality benchmark; these cases must not be presented
as measured candidate recall. Up to32 physical span proposals, five disclosed name
options/span and three complete policies/span-name are distinct units.

After Dirty Mode closure and INT runtime authorization, from the outer shell:

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'legacy-archaeology/src'
python -m unittest discover -s legacy-archaeology/tests/inference -p 'test_*.py'
```

No command above was run, no tests were collected, and no dependencies installed.
The actual producer APIs are `hypothesize(batch,brief,mode='rules')`,
`candidate_diagnostics(generation)` and
`declare_filler(batch,generation,spans,*,actor,reason)`. D5 mapping/export still
requires genuine supporting rulings; these pure producer tests create none.
